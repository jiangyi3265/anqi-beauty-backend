# 数据库脚本

本目录集中保存暨美丽项目的 MySQL 初始化和业务菜单脚本。新开发库按以下顺序导入：

1. `ry_20250522.sql`：若依后端基础表、权限和初始化数据。
2. `anqi-deployment-menus.sql`：管理后台菜单与权限初始化数据。
3. `anqi-admin-menu-layout.sql`：线上的菜单分组（日常业务 / 礼品管理 / 店铺设置）和“商城分类”页面。
4. `anqi-staff-scheduling.sql`：“员工排班”菜单及 `anqi:staff:edit` 操作权限。
5. `anqi-income-config.sql`：“收益管理”菜单及 `anqi:earnings:edit` 收益规则配置权限。
6. `anqi-linkage-1.1.30.sql`：积分商品、积分流水、兑换记录菜单。
7. `anqi-admin-1.1.30-fix1.sql`：收货地址、业务操作记录入口和支付审计（3500）。

按此顺序导入后，新库的菜单与线上 1.1.30 一致：19 个业务页面，“支付审计”只出现一次。第 3 步只用于新库且只执行一次，必须在第 4、5 步之前；在已有库上重复执行会再次隐藏“收益管理”。第 4、5 步依赖第 2 步创建的父菜单，可重复执行，不会覆盖已有菜单，也不会给其他角色授权。

执行前请先创建目标数据库，并根据部署环境配置数据库连接信息。脚本开头已声明 `SET NAMES utf8mb4`。脚本只包含结构和初始化数据，不包含任何数据库密码。

公开仓库的管理员密码为空，不能直接登录；也没有固定的新增用户初始密码。首次导入后，请使用本地 BCrypt 工具生成自己的管理员密码哈希（例如 `htpasswd -nBC 12 admin`，交互输入 5–20 位独立密码后取冒号后的哈希），通过数据库管理工具更新 `sys_user` 中 `user_id=1` 的 `password` 字段。登录后在参数设置中配置新增用户初始密码，或创建用户时单独指定密码。真实密码及生成的哈希均不要保存到仓库。

这些初始化脚本会重建基础表，只能导入新开发库；不能用于覆盖现有业务数据库。

登录密码长度受 `UserConstants.PASSWORD_MIN_LENGTH` / `PASSWORD_MAX_LENGTH` 限制（当前 5–20 位）。它与 `TOKEN_SECRET`、`ANQI_INTERNAL_SECRET` 等服务密钥不同；服务密钥应使用足够长的独立随机值。

已有线上库升级 1.1.30：仅执行 `anqi-linkage-1.1.30.sql`，新增积分商品、积分流水、兑换记录及管理员菜单授权。执行前先核对 3400–3411 中本脚本涉及的菜单编号没有被其他菜单使用；不导入初始化脚本，不重建业务数据。

1.1.30 后台修复 1：再执行 `anqi-admin-1.1.30-fix1.sql`，恢复收货地址、业务操作记录入口并补充支付审计。执行前检查菜单编号 3500 及对应路径没有冲突。需要同时部署包含积分根菜单 3400 的 `SysLoginController` 和新版管理后台；仅插入菜单表不足以保证入口可见。部署后登录检查积分三个页面、会员关联、积分单位、详情及配置保存，不使用真实订单测试收款或退款。
